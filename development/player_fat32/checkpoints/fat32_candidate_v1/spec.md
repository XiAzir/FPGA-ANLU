# FAT32 file playback integration contract

Scope: read-only FAT32 with 512-byte sectors, MBR primary FAT32 type 0x0b/0x0c or a FAT32 VBR at LBA0; no GPT/exFAT/subdirectories/LFN decoding. Enumerate at most four root-directory short-name .BMP regular files, and locate exact short name `TEST    WAV`. Geometry must be FAT32 by cluster count. Current BMP scope is 640x480 bottom-up 24-bit BI_RGB; WAV is 48kHz mono PCM16 with RIFF chunk traversal/padding and actual data length. Keep compact frame buffer data_d1, HDMI/PLL/pins/SDC unchanged. No card writes or format.

All modules clk/rst in 50MHz SD domain. Sector requests are LEVEL signals held until sector end. Source emits exactly 512 valid bytes, may have arbitrary gaps, then end after the last byte (not same cycle). Requesters lower read on end and leave >=3 cycles gap before next request. `sd_read`/`sd_addr` throughout this document refer to physical card sector interface, `file_read`/`file_sector` to a logical sector within a file. Logical payload interface always returns full 512 bytes (parser must respect file_size), only data sectors, not FAT metadata.

## fat32_catalog module (mount and root enumeration)

Ports: input clk,rst,sd_init_done; output reg sd_read, output reg [31:0] sd_addr; input [7:0] sd_data, input sd_valid,sd_end; output reg ready,error; output reg [7:0] error_code; output reg [31:0] fat_lba,data_lba,cluster_count; output reg [3:0] sectors_per_cluster_shift; output reg [2:0] bmp_count; output reg [127:0] bmp_clusters,bmp_sizes; output reg wav_found; output reg [31:0] wav_cluster,wav_size.

Each bmp index i in directory order is `[i*32 +: 32]` in packed descriptors. Mount runs once after init, ready sticky only after catalog scan succeeds, error sticky fatal. Require valid 0x55aa, 512 bytes, SPC power of2 <=128, reserved nonzero, FATs1/2, root entries0, FAT16 size0, total nonzero, FAT32 version0, FAT geometry and root cluster range; honor ExtFlags active FAT when mirroring disabled. Validate FAT capacity, partition/volume/LBA overflow with wide arithmetic. Ignore deleted/LFN/volume/subdir entries; 0 end marker completes scan. Follow root cluster chain when full; mask FAT top4 bits and reject free/reserved/bad/out-of-range; EOC completes root scan. Bounded root scan/hops, error on limit (never infinite). Missing WAV/BMP is not mount error: ready with found/count flags. Return descriptors with valid cluster and nonzero size, malformed selected descriptor produces error rather than issuing invalid LBA.

## fat32_file_sector module (one per BMP/WAV client)

Ports: input clk,rst,enable; input [31:0] fat_lba,data_lba,cluster_count; input [3:0] sectors_per_cluster_shift; input [31:0] start_cluster,file_size; input file_read; input [31:0] file_sector; output [7:0] file_data; output file_valid,file_end; output reg error; output reg [7:0] error_code; output reg sd_read; output reg [31:0] sd_addr; input [7:0] sd_data; input sd_valid,sd_end.

Latch request and descriptors while idle; reject file_sector >= ceil(file_size/512) (33-bit arithmetic), empty/invalid file, geometry/range/overflow. Cache cluster/cluster index for forward sequential requests. Reset traversal on change in start_cluster/file_size or backward cluster request (WAV loops/BMP reread). Map sector using `data_lba + ((cluster-2)<<shift) + sector_in_cluster`; follow FAT32 links as necessary. Read FAT sector(s) through own physical sd interface; only forward payload valid/end in DATA state. Do not expose metadata as file bytes. Bad/truncated/looping chains return sticky error and file_end once to release logical requester; reset required after fatal. Detect loops with bounded traversal and cycle detection or equivalent (document limits), no unbounded walk. `enable=0` quiescent; startup mount has separate physical ownership. Logical requester must drop file_read and leave gap after end; do not reaccept same held request immediately. Mappers supply an additional physical gap across FAT/data/idle transitions.

## tf_wav_file_player module

Ports match old tf_wav_player except omit fixed sector/expected bytes params; add input [31:0] file_size; sd_init_done gates start after catalog ready and wav_found; outputs sd_read and sd_addr mean logical file read and logical file sector. Keep FIFO_DEPTH parameter and sample_take/data/available/primed/error. Parse RIFF/WAVE size bounds, fmt PCM mono48000/blockalign2/bits16/byterate96000; fmt payload >=16 allowed. Traverse unknown chunks and padding, header/fields across sectors; data length must >0, even and within RIFF/file bounds. Support data before fmt by locating it then seeking back after valid fmt (or explicitly reject and document if impossible). Loop exact actual data bytes without output of header/padding/final sector garbage. FIFO sector admission reserves256 samples. Prefetch head and concurrent pop/push correct. Short files prime once sufficient to start including repeated looping; errors sticky, bounded parsing/work by file size. Client source returns full sectors; payload uses absolute byte position and file_size. Preserve old module untouched for checkpoint.

## top integration by main agent

Mount has exclusive card ownership until ready; afterward two mapper physical streams share sector arbiter. BMP directory descriptors feed revised controller, logical sector reads replace raw scan. WAV logical parser sees mapper output. At most two consecutive audio physical sectors when BMP pending (bounded fairness), yielding at sector boundary; mount error or mapper error visible via LEDs. No pixel codec/SDRAM changes. Integration simulation tests mount+fragmented files+RIFF+image bytes through shared arbiter, and fair progress under refill; unit negative cases use synthetic images only. Compile/route before generating independently named FAT candidate; board verification remains user action.
