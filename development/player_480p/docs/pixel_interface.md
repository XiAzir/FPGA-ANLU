# RGB888像素与帧缓存接口（第一阶段）

> 历史阶段说明：接口版已获用户正常反馈，当前工程已升级紧凑24位存储；后续布局、验证边界及位流见[专题记录](<../../../../FPGA-ANLU-docs/开发记录/专题记录/RGB888紧凑帧缓存/2026-10-07.md>)。下文保留第一阶段契约与当时状态。

日期：2026-10-07。当前显示640×480；本文件记录本次已实现的兼容接口以及后续紧凑存储要求。

## 已实现的边界

BMP模块输出24位RGB888。顶层只传递像素、帧索引和读写请求；`frame_buffer_rgb888`内部包含旧帧读写FIFO/控制器和SDRAM包装，负责像素与32位存储字之间的转换。显示侧仍给`video_delay`24位RGB888。

第一版后端仍按`{RGB888,8'b0}`一像素一32位字存储，保持旧帧地址、上下翻转、FIFO、时钟和读延迟。没有节省存储或带宽，没有实现紧凑24位打包。

| 接口 | 所在时钟域 | 契约 |
| --- | --- | --- |
| write_req / write_req_ack | 请求来自write_clk，旧后端在mem_clk确认 | 请求沿用原后端同步；ack沿用既有直接回传路径，未增加回程同步；不是新定义的通用ready/valid接口 |
| write_frame_index | 请求前稳定 | 只允许0/1；一次写请求期间保持稳定；必须是当前非显示缓冲 |
| write_pixel_en / write_pixel_rgb | write_clk | 每个有效脉冲写入一个24位像素；数据与使能同步，沿用BMP生产节奏；本版没有逐像素背压 |
| write_finish | mem_clk | 完整旧后端写入结束的一拍；顶层原toggle CDC和BMP提交逻辑保持 |
| read_req / read_req_ack | 请求来自read_clk，旧后端在mem_clk确认 | 继承原帧读取请求/确认协议 |
| read_frame_index | 请求前稳定 | 只允许0/1，在原帧切换协议允许的边界更新；一次请求期间稳定 |
| read_pixel_en / read_pixel_rgb | read_clk | 数据延迟保持原异步FIFO语义，RGB截取不增加寄存器；video_delay按旧链路捕获，不能假设新零延迟读接口 |
| mem_clk / mem_clk_shift | 存储域 | 50MHz及原移相，沿用原PLL；SDRAM内部地址以32位字为单位，顶层不接地址或传输字数 |

宽高参数在本次实际验证范围内固定640/480。仅增加参数名不表示任意宽高已支持；HDMI时序/BMP/帧控制仍须一并适配。旧索引2/3地址映射不属于支持范围。

只读审查发现旧read/write ack在mem_clk产生后直接接回请求端，未见独立回程同步；本次仅保留既有行为，不把封装解释成已完成CDC修复。后续时钟/握手审计须核准实际时钟关系、确认脉冲宽度和捕获条件。

## 后续紧凑RGB888后端要求（未实施）

保持24位像素语义，将4像素紧凑打包为3个32位SDRAM字。像素数和存储字数独立计数；定义每行字节步长、尾部对齐和写掩码，以及跨字/跨行/帧尾重置。上下翻转以行起址寻址；不能继续按每像素加一个字地址。

通过像素级测试图检查通道顺序和每个像素，覆盖帧首尾、行边界、奇数宽、双帧切换、复位、FIFO短时停顿及音频并发。若以后需要逐像素背压，应单独升级生产者接口并同步改BMP读取；不能在当前无ready接口后面加一个会静默丢像素的后端。

未来存储改造尽量限制在帧缓存内部；新增OSD、亮度/对比度及缩放算法保持RGB888接口。缩放的源图访问能力和双图转场的额外读口仍需明确设计，当前顺序扫描接口不能代表随机访问或两个同时扫描的读口。
