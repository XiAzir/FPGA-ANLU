# Shared mapper B9 bounded review

Review date: 2026-10-21. Scope: read-only RTL review plus focused Icarus test artifacts. No edits to `shared_mapper/candidate.v`, production C11316 sources, or frozen project files. Candidate under review SHA256: `B9A9E3D7FEDCEA5ECF7B1D3272FD5846C54DB2CD2C20EAB4BDE56350A5EB8993`.

## Findings

| Area | Finding | Production reachability / impact |
|---|---|---|
| Timeout priority (`C_SETUP`/`C_DISPATCH`) | B9's watchdog loop is after the core FSM and therefore overrides a same-cycle transition to `C_DISPATCH`; active timed-out request is retired and no new `sd_read` is launched. Focused TB passed. The immutable 6A snapshot reproduces the prior bug: timeout sets `E_TIMEOUT`, but the earlier `C_SETUP` assignment wins and `C_DISPATCH` launches the timed-out data-sector request next. | The collision is RTL-reachable when a client reaches its watchdog boundary in setup/dispatch. For 6A, the queued peer's independent timer can run while a long sector is active; a near-limit queue wait can make the collision possible after owner release. B9 fixes it. Evidence: `tb_review_timeout_priority.*`, `tb_review_timeout_6a.*`, logs below. |
| Timeout concurrent with `C_IDLE` queue selection | If a queued client's timer expires on the exact selection edge, `C_IDLE` can transiently select it and enter `C_SETUP`; the post-FSM watchdog clears `busy/queued`, and the next `C_SETUP` sees `busy=0` and returns to idle before physical dispatch. | The internal one-cycle selection is reachable, but no SD request or client payload results. Focused TB passed. It is a harmless scheduling bubble, not a transaction leak. |
| `C_DRAIN` and disable/re-enable | When disable arrives during an in-flight physical sector, B9 clears client work/cache and enters/retains `C_DRAIN`; request acceptance is gated for the active draining client. Re-enable plus a held fresh request does not consume the old sector suffix; after old `sd_end`, a fresh data-sector request starts at the new request's LBA. | Focused test passed. Current top enables mapper clients from catalog-ready/error signals; reset/error gating is visible in `top_tf_hdmi_audio.v`. Even for a direct interface toggle, the drain behavior preserves old physical transaction ownership. |
| 512th/513th valid coincident with `sd_end` | For data sectors, both candidate and C11316 reference emit byte 512 then classify the sector `E_SHORT` when old `byte_count=511`; for a 513th byte (`byte_count=512`) both suppress the byte and report `E_SHORT`. For FAT sectors, an injected 513th-valid plus `sd_end` collision gives the reference a stale post-error FAT-walk dispatch while B9 stays idle. | The FAT-only collision is unreachable from the current production SD datapath: `sd_sec_read_data_valid=(state==S_READ)&&block_read_valid` while `sd_sec_read_end=(state==S_READ_END)`, and those state predicates are mutually exclusive. Data boundary classifications match. |
| Cache aliases | `cache_cluster[]`, `cache_index[]`, and Brent aliases are combinational aliases of each client's retained `current_cluster[]`, `target_index[]`, `brent_*[]`; they add no independently updated cache payload. `C_SETUP` consumes the old cached index on its RHS before nonblocking updates install the new target. Cache hit is restricted to a valid identity (BMP start/size or static WAV identity) and forward/equal sector index; a completed data sector establishes validity, identity change or disable invalidates it, reset clears it. Client arrays remain separate. | No alias corruption found. Full reference/candidate transaction suite passed 4100 physical transactions, including 4095 BMP FAT hops, BMP cache repeat, WAV sector 0→1 continuation/seek, file identity switch, errors, timeout, reset, and byte/end boundaries. |

## Incremental `C_IDLE` peer-timeout review (2026-10-21)

A follow-up review of the scheduler found an additional parameterized same-edge hazard. In B9, when `active_client` still names BMP from the prior engine owner, `C_IDLE` can select WAV and clear `queued[1]`; the later BMP watchdog assignment can then restore `core_state<=C_IDLE` because it tests the old `active_client` value. WAV can remain `busy=1, queued=0` without a dispatch. This is reproduced from natural reset/arm and real simultaneous `file_read` acceptance with only the BMP timer aged to its expiration threshold. The test uses `WAIT_LIMIT=8` and deposits `wait_count[0]=7`; it does not force `core_state`, `busy`, or `queued`. The default 50,000,000-cycle production reachability of that aged-counter/state combination remains unproven. Separate natural reset/arm tests with `WAIT_LIMIT=1` and `2` time out both requests and show no orphaned request in either B9 or the fix.

The follow-up candidate changes timeout state takeover to require `(active_client==j) && (core_state!=C_IDLE)`, leaving a same-edge `C_IDLE` dispatch intact while still clearing the expired client's request. Independent replay of `tb_cidle_peer_timeout_race.v` produced `REPRO pre-fix` on B9 snapshot SHA `B9A9E3D7FEDCEA5ECF7B1D3272FD5846C54DB2CD2C20EAB4BDE56350A5EB8993` and `PASS idle peer timeout retires only BMP and WAV dispatch proceeds` on fix SHA `084B7DC884B1B33E3EBC2804283BC820B0E5A38EB248E7DC14A6303D70F67BFB`. An independent fixed-snapshot follow-through TB confirms WAV reaches `C_DATA_WAIT` and raises `sd_read` at data LBA 100. Natural parameter-boundary runs (`WAIT_LIMIT=1,2`) pass for both versions and show no orphan; these results bound the current evidence and do not establish default-limit reachability.

Focused evidence is in this directory: `peer_timeout_b9_run.log`, `peer_timeout_fixed_run.log`, `idle_select_peer_timeout_fixed_run.log`, and `natural_limit{1,2}_{b9,fixed}_run.log`; their TB source is `tb_cidle_peer_timeout_race.v` / `tb_cidle_timeout_natural.v` under `../shared_mapper`. The fix snapshot is `candidate_timeout_cidle_fix.v`; its SHA is recorded above. No source in `shared_mapper` or the frozen C11316 project was edited by this reviewer.
