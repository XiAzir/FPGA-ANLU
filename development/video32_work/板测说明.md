# C11332 读突发返回计数候选

## 本轮依据

用户确认C31三种音源均清楚，其余功能正常；视频播放时横向闪条较多，图片切换动画出现横条，静止图片正常。

C32仅修改帧缓存读突发的完成判据：发出256个读请求后，按实际返回的256个数据字结束本组读操作。原实现用最后读命令后的固定10拍间隔判定结束。其余音频、按键、素材格式、SPI、PLL、引脚与约束沿用C31；固定数码管版本改为 `00C11332`，LED继续沿用C31/C29音频历史观察定义。

独立延迟返回消融模型中，旧实现第一次结束时仍有112字未返回，启动JPEG BL4写时有213字未返回，清FIFO时有207字未返回；C32在对应交接点未返回数均为0。真实FIFO、RGB打包/解包、读写backend的像素集成测试在2/10/32/64内存时钟延迟四组通过。详细测试范围与限制见包内binding。

真实SDRAM控制器/器件小模型在旧版ModelSim解析加密初始化模块时编译受阻；C32的现场横条改善情况待本轮上板验证。

最终资源8778/9800 Slice（89.57%），较C31增加97，较C29减少457；62 BRAM、26 DSP。最终Setup/Hold余量+0.393/+0.021ns，TNS均0。构建、源、数据库、最终网表与位流绑定已通过。

## 上板步骤

沿用当前TF卡、外接5V供电、HDMI线及显示器，加载 `video32_read_return.bit`，核对 `00C11332`。

1. 图片静止停留约15秒，听原声并观察细横条。
2. 手动切换四张图片两轮，重点观察下拉动画，记录条带“消失 / 减轻 / 与C31相同”。
3. 进入视频播放约30秒，观察横条，并核对原声、暂停/恢复和KEY0重播。
4. 切换内置音阶听约10秒，恢复原声，再做图片↔视频往返。

先文字反馈横条与三种音源即可。若横条仍出现，保留当前显示状态；后续根据此轮结果确定下一项观测。

TF卡素材继续沿用，音乐和视频仍从TF读取。包内 `video29_media_flow_rollback.bit` 与此前确认正常的C29原文件字节相同。
