# C29被动观测集成只读审查

日期：2026-10-23（北京时间）  
审查对象：`development/player_video29_media_flow/src/user_source/hdl_source`。仅静态检查与C27 top差异审阅；未改候选源，未运行整机仿真或TD。

## 结论

未发现新增观察连线改变播放控制或HDMI/媒体数据路径的意外差异。C29相对C27 top的非空语义差异限于：新增frame-buffer/SDRAM读取旁路观察输出及实例；page3/E/F改接诊断数据；删除旧图片/WAV文件头采样诊断状态。对C27/C29的`top_tf_hdmi_audio.v`做忽略空行/行尾空格的逐块diff，写入、媒体调度、读帧申请/应答、像素源选择、音频gate、AXIS握手、HDMI wrapper和PHY实例控制部分一致。唯一变更到`player_compact_status_pages`的调用是页面展示输入，不进入控制反馈。

packet监视实例取自C28同源 `hdmi_packet_monitor.v`，输入直接接加密HDMI核的并行TMDS数据字，时钟/复位为`video_clk`/`rst_all`，与core输出域相同。`TONE_AMP=24'd1000000`，与`player_audio_probe`内部tone `.AMP(24'sd1000000)`位值一致。页面拼接位宽均为32位，没有发现截断/溢出接线：

- page3：4位标签 + 20位最近ACR N + 8位饱和BCH计数。
- pageE：4位标签 + 4位packet flags + 16位窗口样本数 + 8位饱和TERC计数。
- pageF：4位标签 + 20位最近ACR CTS + 8位饱和tone计数。

monitor窗口`CLK_HZ=25,000,000`与页面计时器同为25MHz视频时钟配置；`packet_samples`的24位窗口输出以低16位显示，单秒48k音频样本在此范围内。错误计数先由monitor 16位饱和，再由top压缩为8位：高字节非零时显示`FF`，否则显示低字节。

## 内存读回观察链

连线从top到真正的异步FIFO写口一致：

`top.memory_* ← frame_buffer_rgb888 debug outputs ← frame_read_write read_capture_* / frame_fifo_read state ← SDRAM Sdr_rd_en/Sdr_rd_dout`

`frame_buffer_rgb888`新增的tap均由原有内部信号直接连续赋值或连接到`frame_read_write`；frame_read_write只把`read_capture_valid`、`read_capture_data`输出到debug口，并把同一对信号接到`rfifo_32_32_512.we/di`。因此观测点描述的是实际写入读回FIFO的beat。默认`MEM_DATA_BITS=32`，SDRAM读数据、捕获数据、FIFO输入以及probe `mem_read_word`均为32位；read FSM状态为4位。

时钟域也匹配信号来源：SDRAM控制/读FIFO供数/读状态/应用层读写计数在`ext_mem_clk`；显示像素、`pixel_de`、raw/gated RGB及underflow sticky在`video_clk`。跨到像素域的读状态、source-valid、read-ack、FIFO-clear使用两级同步器；逐帧读数统计经held bundle + toggle/ack mailbox传递。`page5`为4+8+19+1=32位；page6新增尾字段为4位FSM状态+8位像素侧flags=12位，top的`{4'h6,diag_mem_sync1,memory_probe_page6_tail}`共32位。

一项观测精度限制：page6中的`diag_mem_sync0/1`对16位`debug_memory`逐位用两级同步器跨时钟，未使用原子快照协议。若多个内存状态位同周期变化，页面可能短暂显示混合值；它只驱动数码管诊断，没有连回播放控制。frame-read统计page5使用的bundle则有toggle/ack握手。

## 差异与验证边界

与C27比较，top上新增的播放器可见输出控制改动为零。旧page3的频谱/underflow数据显示被替换为ACR/BCH；pageE/F换成packet monitor计数。page5在C27显示`photo_failure_detail`及reader-error/display-valid/video-mode状态，C28改为scaler progress，C29改为内存会话统计。早期WAV/BMP文件头采样位于旧E/F诊断字，后续已移除。这些属于观测呈现变化。C29新增接口只由`player_memory_runtime_probe`消费；probe没有连接到request、FIFO clear、SDRAM app enable、像素输出或audio valid控制。

`hdmi_packet_monitor.v` C29与C28 SHA256完全一致，复用已验证的单元夹具版本；本轮不重复跑该夹具。此审查为源码静态检查，不证明C29综合/时序/上板通过，也不证明实板packet解码。TD、整机仿真及实板操作均未执行。
