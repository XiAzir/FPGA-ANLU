# C41 刷新门级混合读写合同复核

日期：2026-10-27（北京时间）  
范围：APUG011 v1.2 文档、C41 指定普通门级网表、指定 gate testbench 和根侧报告的运行摘要。只读核查；未运行仿真/TD、未读保护源正文、未改生产源或根 bench。

## 结论

1. APUG011 明确说明应用层读写不可同时操作；每次读写前检查忙/刷新状态，自动刷新模式需等 `Sdr_init_ref_vld` 拉低。读写长度建议为 4 的倍数；每四个数据单元中首地址由用户给出，后 3 个地址按首地址递增。跳地址需满足地址低两位为 `00`，每四拍才可跳一次。
2. 原 C41 traffic bench 不满足地址规则：强制写地址恒为 `0`、读地址恒为 `0x1000`，但每种 enable 连续维持 8 拍，形成重复地址的多拍 burst。它只用来自写 FIFO 后端的 `Sdr_busy` 做门控，也未检查 `Sdr_init_ref_vld`；因此刷新开始时仍可能启动应用访问。读写在逻辑上分段互斥，满足“不同时操作”这一项，但旧 17 拍流没有 burst 间保护空档。
3. 原混合流日志摘要为 req=9、ack=10、AREF=10，并报告一次 AREF 命令间隔 20ns。根侧随后提供的 idle C41 run `run_C41_20261027_190527` 为 req=10、ack=10、AREF=10、全部请求间隔 781 拍且无 unknown。结合 idle 请求路径 PASS 和旧 TB 合同问题，当前证据优先指向混合负载/夹具触发了额外刷新完成活动或请求计数分离；尚不足以推断 C41 控制器本身违反周期刷新约束。
4. 可见 ACK 锥把两路内部状态合成对外 `Sdr_ref_ack`。`ref_ack` 路径由 `Sdr_ref_req && !rw_vld` 采样；`wrrd_ref_ack` 路径由 `ref_vld && sdr_op_over` 采样，语义更贴近刷新窗口内一次操作结束。它可能解释“ACK 没有对应外部周期请求”的现象，但在没有同一波形中的 `ref_vld`、`sdr_op_over`、`rw_vld`、请求与命令沿之前，不能把额外 ACK 定性为普通读写 ACK 或内部自动刷新 ACK。APUG011 还明确指出正常读写由 IP 刷新机制处理，用户通常无需在读写操作中自行管理刷新。

## 普通门级网表证据

文件：`development/player_video41_refresh/build/manual/AC201_tf_hdmi_gate.v`（普通门级逻辑区域）。仅检索并读取下列公开逻辑，没有读取保护正文。

- 109406-109421：`Sdr_busy_n4` 由 `state_reg[1:2]` 解码，并在 SDRAM mem clock 上寄存到 `frame_fifo_write_m0/Sdr_busy`。因此 bench 在 `negedge tb_clk` 读到的是寄存 busy 状态；同一个 `posedge` 后控制状态变化会在门控采样中存在相位/周期边界。
- 109497-109516：对外 ACK 的 LUT 输入是写使能、读使能、`ref_ack`、`wrrd_ref_ack`，再经寄存器输出到 `u1_init_ref/Sdr_ref_ack`。LUT 方程在两路应用 enable 都低时才允许两路 ack 来源通过；混合流边界可能改变可见 ACK 合并/脉冲计数。
- 113765-113775：`ref_ack` 由 `Sdr_ref_req && !rw_vld` 组合后寄存。
- 113740-113746 与 113998-114001：`wrrd_ref_ack` 的寄存器输入为 `ref_vld && sdr_op_over`。
- 113805-113812：`ref_vld` 更新逻辑依赖 `ref_over`、当前 `ref_vld` 与 `Sdr_ref_req`，与刷新控制状态有关。
- 113855-113871：`sdr_op_over` 来自 `rw_vld_1d && !rw_vld`，即有效操作窗口结束沿。

由这些静态连接可知，对外 ACK 是两种内部完成/应答条件的合并观察点，ACK 上升数不能直接视作周期请求上升数。网表连接本身未给出完整 `ref_vld` 状态机含义或 SDRAM 命令发射条件的时序证明；需以波形/命令解码确认自动刷新和读写活动的因果。

## Testbench 合同判断

指定文件：`development/video41_work/gate_refresh/tb_gate_refresh.sv`。

- 第 34-41 行：每个负沿按 `busy === 0` 开启周期性 8 拍 write、8 拍 read、1 拍 idle。两类 enable 不同拍同时为高，因此没有直接违反“不可同时读写”。
- 第 38 行：门控仅检查 write FIFO 后端的 `Sdr_busy`；没有将 `Sdr_init_ref_vld === 0` 纳入读写启动条件。bench 还强制 `rw_vld=0` 仅限 `!TRAFFIC`，故 traffic 时由 DUT 控制器状态处理应用请求与刷新仲裁。
- 第 79-82 行：强制 App 写地址恒为 `0`、读地址恒为 `0x01000`。每连续 8 拍保持同一地址，与每四拍内部地址递增约定不符；若期望重复访问同地址，应按合法 4 拍 burst/地址序列和规范间隔专门构造。
- 地址选择处于四字对齐，但“起始对齐”不能弥补 burst 内部地址递增缺失。
- 空闲用例只覆盖刷新 scheduler/request 路径，不能证明应用读写期间刷新仲裁时序正确。

根侧新测试摘要显示 idle C41 已有 10/10/10 且周期间隔正确。根已说明正在按 4 拍连续递增、`!busy && !ref_vld` 启动和 burst 间 16 拍空档修正 bench；本报告未改动或复跑该 bench。

## 建议的最小判别测试

1. 分别跑 idle、合法 4-word write burst、合法 4-word read burst；读写启动只在 init_done、`Sdr_busy==0`、`Sdr_init_ref_vld==0` 同时满足时发起。每 burst 地址依次为 `A,A+1,A+2,A+3`，`A[1:0]==0`；burst 间保留根侧修订的 16 拍静默。
2. 把长度扩展到 8/12 word，继续每四拍地址递增，分别比较 write-only 与 read-only；之后再测严格互斥的 write→idle→read，不混用同拍使能。
3. 同一采样时钟同时记录并逐沿计数 `Sdr_ref_req`、`ref_ack`、`wrrd_ref_ack`、输出 `Sdr_ref_ack`、`ref_vld`、`sdr_op_over`、`rw_vld`、`Sdr_init_ref_vld` 和 AREF 命令。标出 req→AREF→ACK 延迟，并判断额外 ACK 是否在 `ref_vld && sdr_op_over` 周期形成。
4. 对 AREF 间距以命令实际发出沿计数，而非只看请求脉冲；先用合法应用流复现，再缩减到单一 read/write 模式。若仍有请求计数与 AREF 数不一致，保存完整首个偏差附近波形及源码/网表哈希供根侧复核。
