# C11328 HDMI 与图片进度诊断

此版从 C27 独立建立，用于定位“显示器提示无信号后待机”和图片载入停点。新增信息只进入数码管显示，媒体控制、SPI 12.5MHz、JPEG、音频、PLL 参数、引脚及约束沿用 C27。实板结果待测。

## 操作

1. 保持当前 TF 卡、HDMI 和供电接线，加载 `video28_hdmi_observe.bit`，使用原有 `PROGRAM_SRAM` / JTAG 5MHz 流程。
2. 数码管版本应为 `00C11328`。先保持图片模式，所有按键松开，等待约 15 秒。
3. 录一轮约 20 秒数码管，完整拍清八位。重点为 `2`、`5`、`6`、`B`、`C`、`D`、`E`、`F` 开头的页；显示器的无信号提示和有无声音用文字说明即可。
4. 若图片与声音启动成功，再按原双键长按方式进入视频。若出现故障，保留该状态，按同样方式录一轮数码管。

此轮沿用卡内素材。显示器输入信息菜单这项取证已收齐用户说明，后续以现有“无信号后待机”的反馈为据。

## 本版变化

- E 页替换旧 WAV 文件头页，显示 HDMI 核锁定、输入 SOF 活动、前一帧有效行数。
- F 页替换旧 BMP 文件头页，显示原始 TMDS 时钟字和串行器 ODDR 输入侧时钟活动。
- 5 页在图片无错误时显示 scaler 子状态和输出坐标；图片报错时保留原错误详情。原本的显示有效、视频模式、WAV 与视频读取错误位继续保留。
- 旧 WAV/BMP 文件头采样寄存器已删除；其余原诊断页保留。

## 读数解释

E 页为 `{E, flags[3:0], sof_count[7:0], lines[9:0], events[5:0]}`。

| 字段 | 位 | 意义 |
| --- | --- | --- |
| locked | 27 | HDMI 核当前锁定标志 |
| lock_seen | 26 | 冷启动后曾在媒体复位外观察到锁定 |
| lock_lost | 25 | 媒体复位外观察到锁定下降沿，保持到冷复位 |
| axis_ready | 24 | HDMI 核当前输入 ready |
| sof_count | 23:16 | 输入帧首计数，模 256，持续运行时变化 |
| lines | 15:6 | 上一次 SOF 区间的有效行数，完整源帧预期 480 |
| events | 5:0 | user、valid、HS、VS、曾有 valid 且 ready 低、曾有 DE |

行数在下一次 SOF 锁存。媒体切换会清除当前行数统计；历史锁定、SOF 和事件信息由冷复位清除。ready 等待位记录一次历史观察，需结合当前锁定和行数一起解释。

F 页为 `{F, clock_word[9:0], edges[9:0], 00}`。每 128 个像素时钟周期（名义 5.12µs）统计 ODDR 正边沿输入位的变化数，正常比例约为 256，单次窗口允许同步延迟带来的约 ±2 变化。启动前两个窗口约 10.24µs 后再判断。

F 页观测点位于 ODDR 输入寄存器。ODDR 的 Q 使用器件专用引脚通道，工具禁止将其反馈进内部逻辑；PAD 差分波形、线缆和显示器接收仍属后续物理测量范围。时钟字为 HDMI 核的原始值，页面按其实际值显示。

图片无错误时，5 页中间六位为 `{state[4:0], y[8:0], x[9:0]}`。常见状态：8 等待扇区、7/10/11 取字节、15/16 读行缓存、17 发像素、0 空闲。连续录像能显示坐标是否推进；错误状态下按原错误详情解码。

工程内有解码脚本，例：

```powershell
python development/video28_work/decode_pages.py ED007803 F07D0000 5077E7F2
```

例值仅用于演示字段解码；实际读数以录像为准。

## 离线证据范围

- C27/C28 图片 loader/scaler：16×16 与 640×480 非均匀图像，完整 307,200 像素逐点检查，含 ready 停顿及字节 valid 间隙。两版周期、CRC 和扇区请求统计一致。
- 640×480 用例读取 1,802 次逻辑扇区，包括单独 header 和完整载荷。该输入代表交付备用图几何；实卡文件尺寸仍以实际文件证据为据。
- C28 PHY、被动探针和厂商 EG4 ODDR 模型：多组时钟/复位相位，逐字恢复串行 pin 数据；翻位负控有检出。
- 构建产物及最终时序、源文件与脚本绑定见随包凭据。离线功能模型采用理想时钟，无板端电气测量。
